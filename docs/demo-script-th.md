# บทนำเสนอ 3 นาทีแบบยึดข้อมูลจริง

ใช้เมื่อมีเซิร์ฟเวอร์ที่ได้รับอนุญาตแล้วเท่านั้น เอกสารนี้เป็นบทนำเสนอ ไม่ใช่หลักฐานว่าได้ deploy หรือบันทึกวิดีโอแล้ว ต้องตรวจสถานะจริงก่อนเริ่ม ไม่เปิด fixture ใน production เพื่อเติมชั้นข้อมูลที่ขาด

| เวลา | ทำอะไรใน HEAT//SHIFT | อธิบายอะไร |
|---|---|---|
| 0:00–0:25 | เปิด City Explorer เลื่อน/ซูม เลือกเขต | แผนที่โต้ตอบจริง ขอบเขตทางการ และการแยกเวลาสังเกตการณ์กับเวลาที่ระบบตรวจล่าสุด |
| 0:25–0:55 | สลับอุณหภูมิ NDVI พืชพรรณ และประชากร | LST ไม่ใช่อุณหภูมิอากาศเรียลไทม์ ประชากรเป็นประมาณการที่มีปีอ้างอิง หากแหล่งใด unavailable ให้แสดงเหตุผลตามจริง |
| 0:55–1:20 | คลิกพื้นที่ เปิดรายละเอียด/ประวัติ/องค์ประกอบคะแนน | คะแนน Heat Exposure Priority ย้อนกลับไปดู input/version ได้ ไม่ตีความความร้อนเป็นความยากจน และค่าที่ขาดยังคงขาด |
| 1:20–1:55 | ตั้งงบ 5 ล้านบาทและประเภท intervention แล้วรัน optimizer | เมื่อมี candidate ที่ผ่านหลักฐาน ระบบใช้ OR-Tools เลือกจริงและแสดงบนแผนที่ หากยังไม่มีให้แสดง evidence gate และอธิบายว่ายังไม่ควรเสนอการลงทุนแทนการสร้างโครงการสมมติ |
| 1:55–2:25 | เปิด Scenario Lab เทียบพอร์ต/แผนที่ที่ซิงก์กัน | ทุกพอร์ตใช้งบและสิทธิ์โครงการเดียวกัน baseline ใช้หลักฐานจริง คะแนนประเมินใช้สูตรเดียวกัน ไม่มี before/after heat map ที่สร้างขึ้น หาก baseline ขาดหลักฐานต้องบอกข้อมูลไม่พอ |
| 2:25–2:50 | เปิด Data Observatory ดู source checks, job IDs, validation และประวัติเวอร์ชัน | งานตรวจอัตโนมัติทำตามรอบและใช้ checkpoint; ข้อมูลใหม่ไม่ขึ้นแผนที่ก่อน validation ผู้ดูแลสั่ง refresh ได้เมื่อมีสิทธิ์และ quota พร้อม ไม่จำเป็นต้องสั่งจริงทุกครั้งที่นำเสนอ |
| 2:50–3:00 | ส่งออกรายงานจากผลที่บันทึกไว้ หรือแสดงรายการ readiness ที่ยังติด | แผนผูกเวอร์ชันข้อมูล/ต้นทุนและเก็บผลเดิม ข้อมูลเปลี่ยนจะแจ้งให้คำนวณใหม่ ผลรวมผู้รับประโยชน์ยังไม่หักซ้ำ |

การพิสูจน์ provider update โดยไม่ใช้ข้อมูลดาวเทียมสมมติเป็นข้อมูลจริงให้เปิด CI integration logs แยกจาก production: ผู้ให้บริการจำลองส่ง asset ใหม่ → งานอัตโนมัติ → validation → PostGIS → SSE connection เดิม → map API ได้เวอร์ชันใหม่ จากนั้นข้อมูลไม่ผ่านเกณฑ์ต้องคงเวอร์ชันเดิม ชุดทดสอบระบุเป็น synthetic CI fixture เสมอ

Future Outlook ใช้แสดงประวัติ/เหตุผลที่โมเดลยังไม่ผ่าน หรือ trend scenario ที่ผ่าน temporal/spatial guards จริง ไม่มีการเติมคำพยากรณ์ห้าปีเพื่อให้การนำเสนอดูสมบูรณ์
